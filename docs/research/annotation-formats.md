# PAGE XML vs ALTO XML for the eOCR evaluation corpus

**Checked 2026-11-04.** This compares the current published schemas for multilingual transcription and layout annotations used as an eOCR `Эталонная аннотация`. The recommendation reflects eOCR’s need to preserve page layout, technical graphics, handwritten signatures, and mathematical formulas.

## Version basis

- PAGE’s published page-content schema is dated `2019-07-15`; PRImA’s repository identifies it as the official hosted schema and says `master` contains proposed next-release changes. Pin the dated namespace and XSD rather than an unversioned branch. ([PRImA schema README](https://github.com/PRImA-Research-Lab/PAGE-XML/blob/master/README.md), [PAGE XSD](https://www.primaresearch.org/schema/PAGE/gts/pagecontent/2019-07-15/pagecontent.xsd))
- ALTO 4.4 is explicitly listed as official and released 2023-04-07. The LOC overview also displays “Current version (4.3)” elsewhere, so pin the exact [ALTO 4.4 XSD](https://www.loc.gov/standards/alto/v4/alto-4-4.xsd) and `SCHEMAVERSION="4.4"`, not a floating schema URL. ([LOC ALTO overview](https://www.loc.gov/standards/alto/))

## Capability comparison

| Requirement | PAGE XML 2019-07-15 | ALTO XML 4.4 |
|---|---|---|
| **Transcription and languages** | `TextEquiv` carries `Unicode` and optional `PlainText`; text alternatives can be ranked and scored. Language and script fields occur from page/region down to line/word levels. Language values are drawn from PAGE’s ISO 639.x enumeration. ([PAGE XSD](https://www.primaresearch.org/schema/PAGE/gts/pagecontent/2019-07-15/pagecontent.xsd)) | `String` stores text and supports glyph alternatives; `LANG` uses XML Schema `language`, defaults from page, and can be overridden lower down. `OTHERLANGS` summarizes page languages. ([ALTO 4.4 XSD](https://www.loc.gov/standards/alto/v4/alto-4-4.xsd)) |
| **Page orientation and geometry** | Page width/height and skew orientation are explicit; regions, lines, words, and glyphs can carry polygon coordinates, and text lines can carry baselines. The schema’s geometry is tied to the page image. ([PAGE XSD](https://www.primaresearch.org/schema/PAGE/gts/pagecontent/2019-07-15/pagecontent.xsd), [OCR-D PAGE profile](https://github.com/OCR-D/spec/blob/master/page.md)) | Coordinates use a declared measurement unit (`pixel`, `mm10`, or `inch1200`); blocks and strings have boxes and optional shapes/rotation. Set `pixel` in an evaluation profile to make it directly comparable to image pixels. ([ALTO 4.4 XSD](https://www.loc.gov/standards/alto/v4/alto-4-4.xsd)) |
| **Reading order** | Nested `OrderedGroup` / `UnorderedGroup` structures refer to page regions, with group nesting and indexed references. ([PAGE XSD](https://www.primaresearch.org/schema/PAGE/gts/pagecontent/2019-07-15/pagecontent.xsd)) | Since 4.3, explicit nested reading-order groups reference blocks, lines, or strings; block `IDNEXT` and XML element order also provide flat-order conventions. ([LOC ALTO overview](https://www.loc.gov/standards/alto/), [ALTO 4.4 XSD](https://www.loc.gov/standards/alto/v4/alto-4-4.xsd)) |
| **Tables, graphics, signatures** | Native region classes include `TableRegion`, `ImageRegion`, `GraphicRegion`, `LineDrawingRegion`, and `ChartRegion`. `TableRegion` can declare row/column counts and a coordinate grid; `GraphicRegion type="signature"` is a defined value. It does not define cell objects, merged-cell semantics, or header relationships, so those need a profile or sidecar. ([PAGE XSD](https://www.primaresearch.org/schema/PAGE/gts/pagecontent/2019-07-15/pagecontent.xsd)) | Native blocks are `TextBlock`, `Illustration`, `GraphicalElement`, and `ComposedBlock`. This covers text and broad visual blocks, but there is no table or signature class; applications can agree on tags or user-defined `TYPE` values. ([ALTO layout usage](https://www.loc.gov/standards/alto/techcenter/layout.html), [ALTO 4.4 XSD](https://www.loc.gov/standards/alto/v4/alto-4-4.xsd)) |
| **Mathematical formulas** | `MathsRegion` labels and locates an equation area, but carries no expression tree or mathematical transcription field. Add linked MathML/LaTeX (and a plain transcription if needed) in a sidecar. ([PAGE XSD](https://www.primaresearch.org/schema/PAGE/gts/pagecontent/2019-07-15/pagecontent.xsd)) | No math-specific block or structured expression type is defined. A text block or generic tag can label a formula, but formula structure needs a sidecar or profile extension. ([ALTO 4.4 XSD](https://www.loc.gov/standards/alto/v4/alto-4-4.xsd)) |
| **Image and crop references** | `imageFilename` identifies the page image. `AlternativeImage` with a filename may be attached at page, region, line, word, or glyph level. The schema has no transform mapping a crop/rotated alternative’s local pixels back to the page; the OCR-D profile calls for explicit handling when processing changes pixel positions. ([PAGE XSD](https://www.primaresearch.org/schema/PAGE/gts/pagecontent/2019-07-15/pagecontent.xsd), [OCR-D PAGE profile](https://github.com/OCR-D/spec/blob/master/page.md)) | `sourceImageInformation` identifies source images; illustration/composed-block references can point to external files. There is no generic per-word crop reference or source-to-crop transform. Keep crop asset URI, parent annotation ID, and transform in the corpus manifest. ([ALTO 4.4 XSD](https://www.loc.gov/standards/alto/v4/alto-4-4.xsd)) |
| **Provenance, rights, schema version** | `Creator`, `Created`, `LastChange`, and generic `MetadataItem` cover basic provenance; the dated namespace identifies the schema version. There is no dedicated corpus license field or version attribute, so put corpus/profile version, rights, and richer provenance in a corpus manifest. ([PAGE XSD](https://www.primaresearch.org/schema/PAGE/gts/pagecontent/2019-07-15/pagecontent.xsd)) | `Processing` records processing steps and software; `sourceImageInformation` holds file/document identifiers; root `SCHEMAVERSION` is explicit. ALTO’s CC BY-SA 4.0 notice licenses the standard itself, not the corpus annotations or source images. Record corpus rights and release/profile version separately. ([ALTO 4.4 XSD](https://www.loc.gov/standards/alto/v4/alto-4-4.xsd), [LOC ALTO overview](https://www.loc.gov/standards/alto/)) |

## Recommendation

**Recommendation (inference from the schema features above):** Use **PAGE XML 2019-07-15 as the canonical page annotation**, with a strict eOCR profile. Its typed page regions, page-image geometry, script/direction metadata, explicit reading order, signature label, and table grid cover more of the corpus directly than ALTO. Preserve ALTO 4.4 as an optional interchange/export view.

Keep the base PAGE files schema-valid. Define a corpus manifest keyed by stable page/region IDs for corpus/profile version, license and source rights, source-image hashes, annotator/processing provenance, and crop asset URIs plus coordinate transforms. Use linked sidecars for table-cell semantics (including spans/headers) and formula structure such as MathML or LaTeX. This avoids treating region labels or a standard license statement as richer information than the schemas carry.
